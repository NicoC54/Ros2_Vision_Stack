Pour qu'un robot puisse naviguer dans un environnement inconnu sans repères artificiels (comme les QR codes ou les ArUcos), il doit utiliser l'environnement naturel. C'est la base de l'odométrie visuelle et du SLAM (Simultaneous Localization and Mapping). Le robot va comparer deux images successives prises par sa caméra pour en déduire son propre mouvement.

Pour comparer ces deux images, on ne peut pas comparer chaque pixel un par un : c'est beaucoup trop lourd à calculer, et un mur uni n'apporte aucune information sur le mouvement. L'idée est donc d'isoler des points uniques et très contrastés, de les mémoriser, puis de les retrouver sur l'image suivante.

Voici comment cette mécanique se décompose étape par étape.

### 1. Trouver les points remarquables (La Détection)

Avant de pouvoir reconnaître quelque chose, il faut identifier ce qui est remarquable.

* **Terme technique : Keypoint (ou Point d'intérêt / Feature)**. Un keypoint est un point précis de l'image (des coordonnées X, Y) qui se distingue fortement de son voisinage. Généralement, ce sont des coins ou de fortes variations de contraste. Un pixel blanc au milieu d'un mur blanc n'est pas un keypoint. Le coin noir d'un cadre de porte blanc en est un.

Pour trouver ces keypoints rapidement, la robotique utilise souvent l'algorithme **FAST** (Features from Accelerated Segment Test).
L'algorithme dessine un cercle imaginaire de 16 pixels autour d'un pixel central. Si un arc de cercle continu d'au moins 9 pixels est beaucoup plus clair, ou beaucoup plus sombre que le pixel central, alors l'algorithme déclare : "Ceci est un coin, c'est un keypoint". C'est extrêmement rapide à calculer.

### 2. Décrire ces points pour s'en souvenir (La Description)

Trouver un point sur l'image 1, c'est bien. Mais quand le robot va prendre l'image 2, il va trouver plein d'autres points. Comment savoir quel point de l'image 1 correspond à quel point de l'image 2 ?

* **Terme technique : Descripteur (Descriptor)**. C'est la "carte d'identité" ou l'empreinte digitale du keypoint. Il décrit visuellement ce qui se trouve *autour* du keypoint pour pouvoir le reconnaître plus tard.

On utilise pour cela un algorithme appelé **BRIEF** (souvent combiné avec FAST pour former l'algorithme **ORB**).
BRIEF prend la zone autour du keypoint et choisit des paires de pixels au hasard. Pour chaque paire, il pose une question simple : "Le pixel A est-il plus clair que le pixel B ?".

* Si oui, il note 1.
* Si non, il note 0.
Il fait cela 256 fois. Le descripteur final est donc une suite de 256 zéros et uns (ex: `1001101...`). C'est extrêmement léger en mémoire.

### 3. Faire correspondre les points (Le Matching)

Le robot a maintenant extrait les keypoints et leurs descripteurs de l'image 1, et ceux de l'image 2. Il doit maintenant trouver les paires.

* **Terme technique : Feature Matching**. C'est l'action de comparer la liste des descripteurs de l'image 1 avec la liste de l'image 2 pour relier les points identiques.

Puisque nos descripteurs ORB sont des suites de 0 et de 1, la comparaison est triviale pour un ordinateur. On utilise la **Distance de Hamming**. On superpose la chaîne de 0 et de 1 du point A (image 1) avec celle du point B (image 2). La distance de Hamming est simplement le nombre de différences entre les deux chaînes. Si la distance est très faible (très peu de bits différents), l'ordinateur conclut : "C'est le même point physique".

### 4. Filtrer les erreurs (Le RANSAC)

À ce stade, l'ordinateur a tracé des lignes entre l'image 1 et l'image 2 pour relier les points. Mais le monde réel est chaotique. L'algorithme de matching s'est forcément trompé sur certains points : il a pu confondre deux feuilles du même arbre, ou relier un objet physique avec son propre reflet dans une vitre.

* **Terme technique : Inliers / Outliers**. Les *inliers* sont les bonnes correspondances (qui suivent la vraie logique physique du mouvement de la caméra). Les *outliers* sont les erreurs mathématiques de matching (le bruit).

Si on calcule le mouvement du robot en utilisant les *outliers*, le robot va penser qu'il a été téléporté ou qu'il tourne sur lui-même de manière aberrante. C'est ici qu'intervient **RANSAC** (Random Sample Consensus).

RANSAC est un filtre probabiliste basé sur la démocratie.

1. Il prend une poignée de points au hasard parmi tous les matchs trouvés (par exemple 4 points).
2. Il crée une hypothèse mathématique de mouvement : "Si ces 4 points sont justes, cela veut dire que la caméra a bougé de 5 centimètres vers la droite".
3. Il teste cette hypothèse sur **tous les autres points** restants. Il leur demande : "Êtes-vous cohérents avec un mouvement de 5cm vers la droite ?". Il compte combien de points répondent "Oui" (le consensus).
4. Il recommence ce processus de tirage au sort des milliers de fois.
5. À la fin, il garde l'hypothèse de mouvement qui a obtenu le plus grand consensus. Tous les points qui ne sont pas d'accord avec cette hypothèse gagnante sont déclarés *outliers* et jetés à la poubelle.

# Fiche de cours : Extraction de Features et Matching (Base SLAM)

## 1. La Pipeline de l'Odométrie Visuelle

L'odométrie visuelle permet d'estimer la position et l'orientation (pose) d'un robot en analysant une séquence d'images. Le processus classique se découpe en quatre grandes étapes consécutives :

1. Extraction des Keypoints.
2. Calcul des Descripteurs.
3. Matching des features entre les images $I_{t-1}$ et $I_t$.
4. Rejet des outliers (RANSAC) et estimation du modèle géométrique.

## 2. Détection (FAST) et Description (ORB)

Pour traiter des flux vidéo en temps réel sur des robots embarqués (ex: drones), on privilégie l'algorithme **ORB** (Oriented FAST and Rotated BRIEF), qui est une alternative libre de droits, rapide et efficace à SIFT et SURF.

### Le détecteur : FAST

FAST identifie les coins (*corners*). Il évalue un cercle de 16 pixels de rayon autour d'un pixel candidat $p$. Si au moins $N$ pixels contigus sur ce cercle sont tous significativement plus clairs ou plus sombres que le pixel central $p$ (d'un seuil $t$), le point est qualifié de *keypoint*. L'avantage majeur de FAST est sa vitesse de calcul d'où son omniprésence dans le SLAM temps-réel.

### Le descripteur : BRIEF (adapté dans ORB)

ORB attribue une "empreinte" binaire au keypoint. Il sélectionne des paires de pixels $(x, y)$ dans le voisinage du keypoint.

* Si l'intensité de $x < y$, le bit vaut 1.
* Sinon, le bit vaut 0.
ORB améliore BRIEF en y ajoutant l'invariance à la rotation : il calcule le centre de masse des pixels autour du keypoint pour trouver son orientation principale, et tourne le motif de comparaison de BRIEF en fonction de cet angle. Un keypoint regardé à l'envers gardera ainsi la même signature binaire.

## 3. Feature Matching (Distance de Hamming)

La comparaison de vecteurs binaires est exécutée via la **Distance de Hamming**. Elle compte le nombre de bits qui diffèrent entre deux descripteurs.
En C++, cela se traduit par une opération bit-à-bit temporelle (XOR suivi d'un comptage de bits à 1), ce qui est extraordinairement optimisé par les processeurs modernes.

On utilise souvent un **Brute-Force Matcher (BFMatcher)**. Pour chaque descripteur de la première image, le matcher calcule la distance avec *tous* les descripteurs de la seconde image et conserve le plus proche.

## 4. Rejet des Outliers : RANSAC

RANSAC (*Random Sample Consensus*) est un algorithme itératif permettant d'estimer les paramètres d'un modèle mathématique à partir d'un jeu de données contenant des données aberrantes.

**L'algorithme RANSAC appliqué à la vision :**

1. **Échantillonnage :** Sélection aléatoire d'un sous-ensemble minimum de matchs (ex: 4 matchs pour calculer une homographie, 8 pour une matrice fondamentale).
2. **Estimation :** Calcul du modèle de transformation mathématique basé uniquement sur cet échantillon.
3. **Évaluation :** Test de tous les autres matchs restants contre ce modèle. Si un match correspond à la prédiction du modèle (avec une certaine tolérance d'erreur), il rejoint l'ensemble des *inliers*.
4. **Itération :** Répétition des étapes 1 à 3 un nombre défini de fois.
5. **Sélection finale :** Le modèle ayant accumulé le plus grand nombre de votes (*inliers*) est conservé. Le modèle final est ensuite recalculé de manière optimisée en utilisant l'intégralité du groupe d'inliers gagnant.

## Exemple de Code C++ (OpenCV)

Ce script minimal illustre la pipeline complète : extraction ORB, matching, et filtrage RANSAC via le calcul de l'homographie.

```cpp
#include <opencv2/opencv.hpp>
#include <vector>
#include <iostream>

void featureMatchingAndRANSAC(const cv::Mat& img1, const cv::Mat& img2) {
    // 1. Initialisation de l'extracteur ORB
    cv::Ptr<cv::ORB> orb = cv::ORB::create();

    std::vector<cv::KeyPoint> keypoints1, keypoints2;
    cv::Mat descriptors1, descriptors2;

    // 2. Détection (FAST) et Description (BRIEF/ORB)
    orb->detectAndCompute(img1, cv::noArray(), keypoints1, descriptors1);
    orb->detectAndCompute(img2, cv::noArray(), keypoints2, descriptors2);

    // 3. Matching avec la distance de Hamming
    // crossCheck=true force le match à être mutuellement le meilleur
    cv::BFMatcher matcher(cv::NORM_HAMMING, true);
    std::vector<cv::DMatch> matches;
    matcher.match(descriptors1, descriptors2, matches);

    // Extraction des coordonnées 2D (Points) à partir des matchs bruts
    std::vector<cv::Point2f> points1, points2;
    for (size_t i = 0; i < matches.size(); i++) {
        points1.push_back(keypoints1[matches[i].queryIdx].pt);
        points2.push_back(keypoints2[matches[i].trainIdx].pt);
    }

    // 4. Application du RANSAC via le calcul de la transformation (Homographie)
    // mask contiendra 1 pour les inliers (bons matchs) et 0 pour les outliers
    std::vector<uchar> inliers_mask;
    cv::Mat homography = cv::findHomography(points1, points2, cv::RANSAC, 3.0, inliers_mask);

    // Comptage pour analyse
    int inliers_count = 0;
    for (size_t i = 0; i < inliers_mask.size(); i++) {
        if (inliers_mask[i]) {
            inliers_count++;
        }
    }

    std::cout << "Matchs bruts trouvés : " << matches.size() << std::endl;
    std::cout << "Bons matchs (Inliers après RANSAC) : " << inliers_count << std::endl;
}

```
